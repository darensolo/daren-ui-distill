# 阶段 0.5 —— 复刻计划 / 任务验收清单

阶段 0 给你事实基线；阶段 0.5 把事实基线转成可执行、可验收的计划。不要跳过本阶段直接写代码。

## 核心原则

复刻质量来自「拆解 → 映射 → 执行 → 检查 → 改进」循环：

1. **拆解**：对照源应用，把主界面区域、组件、状态、交互点逐项列清。
2. **分层**：按 L1 令牌（Tokens） / L2 组件（Components） / L3 模式（Patterns） / L4 模板（Templates） 拆出事实、实现和验收项。
3. **映射**：先映射到源版复刻（Source Replica）的原版基准版本（benchmark），再映射到目标设计系统的 token、组件、设计模式。
4. **执行**：先完成 源版复刻（Source Replica），再完成设计系统适配（Design-System Adaptation）；只执行计划里有验收标准的任务。
5. **检查**：用浏览器和清单逐项验收，记录通过 / 失败 / 后续。
6. **改进**：失败项回到计划或实现中修正，再次验收。

如果用户只要求快速草图，可以说明你将降级为静态原型；否则默认必须走完整循环。

## 输出格式

计划建议写成一个 Markdown 文档，放在当前原型或设计文档附近，例如：

`docs/daren-design/plans/<app>-replica-plan.md`

也可以在对话中先输出草案，得到确认后再落文件。计划必须包含以下章节。

## 9. 验收流程

每轮执行后按顺序检查：

1. **代码质量**：类型检查 / lint / 构建通过。
2. **源版复刻（Source Replica） 视觉截图**：对照源应用桌面和必要移动视口截图；区域、颜色、间距、文字不重叠。
3. **适配（Adaptation） 视觉截图**：对照 源版复刻（Source Replica）；结构和交互不漂移，视觉身份切换到目标设计系统。
4. **点击巡检**：按交互矩阵逐项点击、hover、切换、拖拽；源版复刻（Source Replica） 与 适配（Adaptation） 都要验。
5. **主题巡检**：浅 / 深色切换后无硬编码漏色，无布局跳动。
6. **缺口记录**：失败项回到任务清单；暂不做项必须是 `deferred` 并有用户可见反馈。
