# 阶段 2 —— 设计系统适配（Design-System Adaptation）：替换进目标设计系统

D24 page 分支兼容锚点：

- 宿主提供旧 D24 `replica-fidelity-contract.md` / `invocation-contract.md` 时，读取其中 page 契约；独立插件不得假设固定仓库或绝对路径。
- 宿主未提供旧契约时，以随插件发行的 UI Distill contracts/runtime 为准；无法安全映射的旧字段 fail closed。
- 目标 v0.1：Daren Design；任意目标设计系统为 v0.2 参数化路线
- 设计系统 machine gates：从当前宿主 `package.json` 发现并选择 `tokens:lint`、`design-harness:check` 与结构/source report；不硬编码宿主路径

优先使用独立的 `design-system-adapter` skill 完成本阶段。本文件只说明 ui-replica-engine 如何把源版复刻（Source Replica） 交接给适配器（adapter），以及适配器（adapter） 完成后 ui-replica-engine 应如何回归验收。

你已经有了一份阶段 0 基线文档，已经按 `plan.md` 输出阶段 0.5 复刻计划 / 任务验收清单，并且已经完成阶段 1 源版复刻（Source Replica）。现在在源版复刻（Source Replica）的结构和交互不变的基础上，把视觉身份替换进目标设计系统，使其**布局与交互读起来与源应用 1:1 一致**，同时**每一处视觉都是用户自己的设计系统**。本文件就是为此而设的方法论。

阶段 2 的第一条规则：**不重做复刻，只替换系统。** 如果源版复刻（Source Replica）本身不准，先回到 `source-replica.md` 修正；不要在设计系统替换阶段一边改结构、一边改视觉。

阶段 2 的第二条规则：**只执行计划中有输入依据和验收标准的 适配（Adaptation） 任务。** 如果实现时发现计划漏了某个区域、按钮、状态、token 或设计模式，先补计划，再改代码。

## 交接给 design-system-适配器（adapter）

交接材料：

-源版复刻（Source Replica）路由 / 文件 / 截图。
- 阶段 0 基线中的 L1-L4 事实表。
- 阶段 0.5 plan 中的 L1-L4 映射表、交互矩阵和 适配（Adaptation） 任务。
-源版复刻（Source Replica）验收记录。
- 用户指定的目标设计系统路径，例如 Daren Design 的 token、primitive、pattern、template 文档。

适配器（adapter） 的额外产出：

- 设计资产审计（Design Asset Audit）：先自动检查源版复刻（Source Replica）资产与目标设计系统现有资产，输出查缺补漏建议。
- 适配器（Adapter） Plan。
- 适配后界面（Adapted UI）。
- 演进提案 / 报告（Evolution Proposal / Report）：可反哺设计系统的 Foundations / 组件（Components） / 模式（Patterns） / 模板（Templates） 候选；未经人工确认不得写入设计系统真源。
- 验证记录（Verification Record）。

## 第 1 步 —— 在写任何 CSS 之前先学习目标 token

你是*映射到*已有的东西之上；不要另起一套平行调色板。找到项目的设计 token 来源并读懂它：

```bash
# 常见形态 —— 看项目用的是哪一种
find . -name '*tokens*.css' -o -name 'tailwind.config.*' -o -name 'theme.*' \
  | grep -v node_modules
grep -rE -- '--color-|--space-|--radius-|--font-|--size-|--text-' \
  <token-file> | sort -u
```

在脑中（或写下来）建立一份清单：语义化颜色 token、间距刻度、圆角刻度、排版 token，以及任何控件尺寸 token。阶段 0 §3 的表格已经提出了映射建议——把它们与这里实际存在的东西对照核实。如果缺少某个需要的语义化 token，优先把它*加进设计系统*，而不是在行内写死一个值。

把这个清单落到阶段 0.5 计划的 L1-L4 映射表里。没有进入映射表的视觉值，不应进入代码。

## 第 2 步 —— 共享外壳，可插拔的导航 + 面板

即便你只复刻一个应用，仍要把外壳构建成**导航模型**和**面板内容**可替换的形式——这几乎是免费的，并且一旦出现第二个相似应用（或一个变体）就立刻回本。具体来说：一个布局组件，拥有区域网格 + 标题栏 + 输入区插槽 + 侧面板插槽，并把导航树和面板渲染器作为 props / children 传入。

为外壳保持单一的 CSS 命名空间（例如一个简短的类前缀）和单一的布局 token 组（下一步），让复刻品自成一体、易于查找。

## 第 2.5 步 —— 可操作元素必须真的可操作

复刻不是截图重绘。阶段 0 的基线必须列出主界面上所有可见交互点，源版复刻（Source Replica） 必须先逐项实现并验收；阶段 2 替换设计系统后，交互矩阵必须再次通过：

- **按钮 / 图标按钮**：点击后要出现源应用同类反馈，例如切换面板、打开菜单、弹出空态、切换状态、触发 toast，或在功能不可用时呈现 disabled / unavailable 状态。
- **tabs / 面板入口**：必须能切换 active 状态并刷新对应内容；多 tab group 要保留焦点态差异。
- **文件树 / 导航树**：展开、折叠、选中、hover、active、空文件夹和长文件名截断都要有行为。
- **更多菜单 / 命令入口**：即便真实命令尚未接入，也要有菜单壳、菜单项、分隔线、禁用项和关闭行为，而不是无响应按钮。
- **split / resize / collapse**：可拖拽的地方至少要实现可拖拽调宽 / 折叠 / 恢复；若范围受限，要有 min / max。
- **状态栏 / 主题 / 模式切换**：状态变化要反映到 UI，并保持持久化或本地状态。

任何无法实现的交互，都要在交付时列为明确缺口，不能把无响应的按钮当作完成。设计系统替换不得让已通过的源版复刻（Source Replica）交互退化。

## 第 3 步 —— 结构 → 一个专用的布局 token 组

创建一组*只*承载结构尺寸的 token：

```css
:root {
  --layout-<app>-titlebar-h: 52px;
  --layout-<app>-sidebar-w: 300px;   /* 默认值；用户可调整，最小 220 / 最大 420 */
  --layout-<app>-thread-w: 768px;    /* 若 CSS 中有则取确切值 */
  --layout-<app>-rightpanel-w: 420px;/* 默认值；最小 320 / 最大 560 */
}
```

任何不是结构尺寸的东西——颜色、间距、圆角、字体、控件尺寸——都复用已有的语义化 token。不要把间距刻度重复进这个组里。结构 token 的默认值应来自源版复刻（Source Replica），而不是重新看截图再估一遍。

## 第 4 步 —— 视觉 → 语义化 token（是映射，不是粘贴）

应用阶段 0 §L1-L4 与阶段 0.5 映射表。反复出现的判断题：

- **强调 / 品牌色只出现在源应用使用它的地方** —— 图标、行内链接、焦点环、小徽标。绝不因为源应用的色值好看就把它提升为大面积背景。把它映射到目标的 `--color-brand` / `--color-blue` / 等价物，并保持同样微小的覆盖面积。
- **选中 / 悬停保持中性**，除非目标系统明确为它们设定主题——例如行悬停用 `--color-muted`，活动行用中性的 `--color-sidebar-accent`，*而非*品牌色，哪怕源应用给它上了色。
- **字体**：UI → 目标的 `--font-sans`；代码 / diff / 终端 → `--font-mono`。绝不引入源应用专有的字体文件。
- **图标（例外，不替换）**：直接沿用源应用提取出的原图标资源（SVG / 图标字体等），保持图形语言与源应用 1:1 一致——**不**映射到目标系统的图标集。这是本技能里唯一保留源资源的视觉元素；颜色 / 字体 / 圆角 / 间距 / 组件库仍照常映射到用户自己的 token 与组件。注意：图标的*描边色 / 填充色*仍走语义化 token（例如 `currentColor` 继承 `--color-foreground`），只是图标的*形状路径*沿用源应用。
- **亮 / 暗色**：因为一切都落在语义化 token 上，主题切换应当无需任何单色覆盖即可工作。如果你发现自己在为复刻专属的颜色写 `.dark` 覆盖，那就是一个信号——你把某个值写死了。

## 第 5 步 —— 不要编造「官方」数值

任何源应用作为用户状态存储的东西（侧边栏宽度、面板宽度、哪个面板是打开的）都没有官方值。源版复刻（Source Replica） 里选定的合理默认值可以沿用到适配（Adaptation），但要在代码 / 注释里把它标注为默认值，给它最小 / 最大值，并像源应用那样持久化它（本地状态）。把一个截图估算的宽度当作规格来呈现，是这些基线日后误导工作的最常见方式。

## 验证坑点（来之不易；在宣布完成前逐项检查）

这些在各次复刻中反复出现，被遗忘时最浪费时间：

- **开发服务器端口必须与配置一致。** 如果框架配置设了一个非默认端口（例如 Vite `server.port: 5176`），预览 / 启动配置就必须用那个确切端口——否则预览代理连不上，浏览器会卡在 chrome-error 页面。检查实际配置值，不要假设默认值。
- **预览代理无法硬跳转到子路由。** 通过代理加载 `localhost:<port>/<subroute>` 经常会被弹回 `/`。要落到某个子路由，要么直接打开开发服务器，要么在应用挂载后用客户端跳转（`history.pushState('/<route>'); dispatchEvent(new PopStateEvent('popstate'))`）。
- **确认开发服务器跑的是*正确的*仓库 / worktree。** 如果复刻品在主仓库里，但开发服务器是从另一个缺少新路由的 worktree 启动的，你会得到 404 并去追一个幻影 bug。核实服务目录。
- **干净的类型检查与控制台。** 在宣布完成前，争取在复刻路由上做到零类型错误、零控制台错误 / 警告。一个看起来 1:1、但控制台噪声满天飞的布局，并没有完成。
- **主界面点击巡检。** 用浏览器逐个点击首屏可见按钮、tab、折叠器、菜单入口、文件树项、状态栏入口和主题 / 模式切换。每一项都要产生可见反馈，或明确 disabled / 空态；无响应按钮视为未完成。
- **按计划验收，而不是按感觉验收。** 对照阶段 0.5 的任务清单和交互矩阵，把每一项标成 `verified`、`blocked` 或 `deferred`。失败项必须进入改进循环，不能在最终答复里被一句“基本完成”带过。
- **回归源版复刻（Source Replica）。** 适配（Adaptation） 完成后，把关键截图和点击巡检结果与源版复刻（Source Replica）对照。结构、状态和交互不应因为 token / primitive / pattern 替换而漂移。

当布局与交互读起来 1:1、主界面所有可见操作点都有反馈、每一处视觉都落在用户自己的 token 上、亮 / 暗色切换干净、控制台干净，并且源版复刻（Source Replica）回归无结构 / 交互退化时——阶段 2 就完成了。
